# Prior art — code understanding tools (2026-10-18)

Read-only study of the closest open-source tools before redesigning Umbra. Repos were cloned and read, not run. Star counts and benchmarks were not verified.

## Summary

None of the studied tools combines the three things Umbra promises:

1. Every edge traceable to an exact source span, tagged Fact / Hypothesis / Observation.
2. Journeys with inputs, outputs, condition branches and error paths, confirmed by runtime evidence.
3. Sync triggered by each Claude Code edit, scoped to the edited code.

Decision input: build Umbra's own core (domain model, provenance store, zoom and Journey engines). Reuse libraries and MIT/Apache parts; take ideas from the rest.

## Claude Code integration (from official docs)

- Hooks are the reliable channel: `UserPromptSubmit` (the request), `PostToolUse` on `Write|Edit|MultiEdit` (file + old/new strings), `Stop` (`last_assistant_message`, i.e. Claude's explanation), `SessionStart` / `SessionEnd`. Use `type: "command"` with `async: true` so Claude never waits.
- The transcript JSONL format is internal and changes between versions: never parse it.
- Skills are invoked by model judgement, so they cannot be the recording mechanism.
- MCP is pull-only; a plugin can bundle a local MCP server.
- A file watcher is still needed for edits made through Bash or by the user.
- Background `claude -p` on a subscription is a policy grey zone for a tool; a product must use an API key. Run internal calls with `--bare` to avoid hook recursion.
